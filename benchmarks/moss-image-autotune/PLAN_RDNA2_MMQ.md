# RDNA2（wave32）量化 GEMM 内核：调研与实施计划

## 1. 调研结论（事实）

1. **不需要从零写内核**：`ggml/src/ggml-vulkan/vulkan-shaders/mul_mmq.comp` 已经是
   wave-32 参数化的通用 MMQ 内核，特化常量齐全：

   | 常量 | 默认 | 含义 |
   |---|---|---|
   | `BLOCK_SIZE` | 64 | 工作组线程数（local_size_x） |
   | `BM` / `BN` | 64 / 64 | 每工作组输出 tile |
   | `WM` / `WN` | 32 / 32 | 每 warp（wave）输出 tile |
   | `WMITER` | 2 | 每 warp 的迭代数 |
   | `TM` / `TN` | 4 / 2 | 每线程输出元素 |
   | `WARP` | 32 | **显式建模 wave32** |

   即"RDNA2 wave32 内核"= **在现有 MMQ 上做参数搜索 + 生成新的 pipeline 变体**，
   与我们在 int8 内核上调 TILE_N/TILE_R 是同一类工作。
2. 该内核依赖 `GL_EXT_integer_dot_product`（dp4a），本卡支持（`int dot: 1`）；
   coopmat 版本 `mul_mmq_cm1.comp` 在 RDNA2 上不会被选用。
3. 实测效率（Qwen-Image-2.1 edit，1024²）：
   - Q5_K 24576×4096×4096：2.20 s → **375 GFLOP/s（fp16 峰值 12.6 TFLOP/s 的 3%）**
   - Q6_K 4096×4096×4096：1.50 s → 91 GFLOP/s
   - 两项合计占单步 61%，是 Qwen 类 Q4–Q6 GGUF 的共同瓶颈。
4. 低效率的结构性来源是 **K-quant 解包（Q5_K 的 5-bit 提取 + 偏移还原）** 与
   tile 复用不足，而不是 dp4a 指令（MOSS 上已证明 dp4a 全速率）。

## 2. 目标

把 Q5_K/Q6_K 的 matmul 吞吐从当前 375 GFLOP/s 提升 30–100%（e2e 期望 −8 %～−20 %），
且**不改变数值**（int32 累加必须与现行路径逐位一致，否则视为新路径需单独评估）。

## 3. 实施步骤

| 阶段 | 内容 | 验收 |
|---|---|---|
| S1 | 建微基准：Q5_K/Q6_K 的真实形状（24576×4096×4096、4096×4096×4096），复用 `ggml_i8bench.cpp` 的骨架，直接跑 `GGML_OP_MUL_MAT` | 输出 FNV + ms，与 e2e 里的算子耗时对得上 |
| S2 | 参数搜索：先单变量（`BLOCK_SIZE` 64→128/32），再 `BM/BN`（32/64/128）与 `WM/WN`、`WMITER`、`TM/TN` 组合；每次改 pipeline 的特化常量，编译后测 | 找到 ≥ +30 % 的组合 |
| S3 | 数值验证：与现行 MMQ 输出 FNV 比对；不同累加顺序则改为与 fp32 参考比（当前路径的误差带） | 逐位一致或误差不劣于现行 |
| S4 | 端到端：Qwen-Image edit 1024²/8 步、1 张参考图、`--offload-to-cpu`，交叉 A/B 各 2 次 | wall −8 % 以上 |
| S5 | 回归：MOSS（int8 路径不受影响）、其它 Q4/Q5/Q6 模型抽样 | 无回归 |

## 4. 风险

- **Pipeline 数量爆炸**：每个组合都要编译一组 SPIR-V，启动时间和显存会涨；需要限制组合数、
  并且只对实际用到的量化类型创建。
- **寄存器/共享内存上限**：`BM=BN=128` 在 wave32 + 无矩阵核下可能溢出，需逐步加。
- **数值漂移**：tile 改变会改变 int32 累加的归约顺序；K-quant 路径通常是先解包成 int8 再
  dp4a，累加仍是整数，理论上可逐位一致，但需实测确认。
- **上游合并**：即使本地有效，也需要能说服上游参数化的合理性（用 Qwen/MOSS 两组数据背书）。

## 5. 首个里程碑（建议先做这一步）

只调 `BLOCK_SIZE`（64→128 与 64→32）与 `BM/BN`（64/64 → 128/64、64/128），共 4 个配置，
在 S1 微基准上测；任一配置 **≥ +15 %** 才继续 S2，否则判定该路径在本卡无空间，停止。

## 6. S1 结论（2026-10-30）：计划提前终止

微基准（`mmq_bench.cpp`）实测 Q5_K 68.05 ms = **12.1 TFLOP/s**、Q6_K 11.61 ms = **11.8 TFLOP/s**，
与 e2e 日志的**单次调用**时间完全一致（日志里 2.20 s 是 32 次调用之和，不是一次）。
第 3 节的效率前提（375 GFLOP/s、fp16 峰值 3%）是把每步合计当成单次调用算错了。

MMQ 已跑到约 packed-fp16 峰值的一半，S2 参数搜索的预期收益 < 5 %，不满足 ≥ +15 % 的门槛。
**结论：不进入 S2/S3/S4，RDNA2 量化 GEMM 路线关闭。** 若将来要动，方向应改为 attention。
