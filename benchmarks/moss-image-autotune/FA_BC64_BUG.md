# FA 偶发正确性缺陷调查报告（P0）

日期：2026-10-30 · 设备：RX 6700 XT（gfx1031 / RDNA2 / RADV）· 二进制：P0 前 `sdcli-pre-p0`（md5 0f14b236…）

## 1. 症状

第一阶段观察到：同样输入、同样二进制、同样 seed，两次运行的 `pred_s001` 相对误差 2.4–4.0 %；
`--flash-attn diffusion=off` 时逐位一致；固定 `--max-vram` 也不能消除。隔离测试（同一 FA 内核用
真实 Q/K/V 重复调用）出现少量元素差异。

## 2. 调查过程与结论（按时间顺序）

### 2.1 导出保活陷阱（测量方法修正）

只 `ggml_build_forward_expand` 而不 `ggml_set_output` 时，中间张量显存会被后续节点复用，导出到的是
别人的数据。第一版因此得到"l1…l41 完全相同"的错误结论。修正后 layer 0 的 q/k/v/attention 输出逐位一致。

### 2.2 隔离复现（`fa_determinism.cpp`）

真实 Q/K/V（layer 0，24 heads，L=10812），同一 graph 重复调用，逐次与 iter0 比对：

| 批次 | 配置 | 调用 | 出现差异的调用 |
|---|---|---:|---:|
| A | 默认（Bc=64，subgroup 归约） | 240 | 11（4.6 %） |
| B | 强制 vec4-shuffle workaround（上游针对 RDNA2 Windows 的已知问题） | 239 | 54（22 %，且改变了舍入） |
| C | **Bc=32（上游 D=128 默认）** | 240 | **4（1.7 %）** |
| D | **禁用 subgroups（shmem 归约）** | 239 | **0** |
| E | 禁用 subgroups，L=10812 | 1000 | **0** |

差异元素数量 1–40 个，位置分散（实测 d ∈ {0,3,7,65,68,69,88}）——**第一阶段"恒为 d=69"是小样本
造成的误判**。幅度从 1e-4 到 6.7（垃圾值级）都有。

对照 C 是关键：**Bc=32 同样会出错**，因此缺陷不是上一轮 `block_cols=64` 引入的，而是 FA 标量内核
在 RADV/gfx1031 上的既有问题。回退 Bc 不能恢复确定性。

### 2.3 排除项

| 假设 | 证据 |
|---|---|
| 主机端读回竞争 | 同一同步点连续两次 `tensor_get` 完全一致（无 readback mismatch） |
| f16vec4 `subgroupShuffleXor` 已知缺陷（上游 flag 8 的 workaround） | 强制开启后异常率反而升高（54/239）→ 不是它 |
| 显存/分页压力 | 隔离测试只占 ~150 MB，仍复现 |
| 计划漂移 | 模型级：固定 `--max-vram 10` 后工作区完全相同，仍不一致 |
| 权重/预取/惰性加载/线程/RNG | 全部逐位一致或无效 |

### 2.4 根因定位

把归约从 **subgroup shuffle + 跨 subgroup LDS 合并** 改为 **shmem 树归约**（`SubGroupSize=0`，
即 `disable_subgroups`，Intel 早已使用的路径）后：

- 真实数据 239 次调用 **0 差异**；随后 1000 次调用 **0 差异**；
- 与 CPU 参考相比精度不变：`rms 5.94e-06`（原路径 5.95e-06），`max_abs 5.42e-05`；
- **更快**：L=10842 时 182.5 ms vs 196.2 ms（−7 %）；L=4120 时 28.7 vs 31.4 ms（−9 %）。

结论：缺陷位于 `flash_attn.comp` 的 subgroup-shuffle 归约路径（wave32、`subgroupShuffleXor` 链 +
`tmpsh/tmpshv4` 跨 subgroup 合并）在 RADV/gfx1031 上的实现/代码生成。未进一步定位到单条指令
（需要 ISA 级对照），但修复不需要该细节。

## 3. 修复

`ggml-vulkan.cpp` / `get_fa_tuning_params_scalar`：

```cpp
if (device->vendor_id == VK_VENDOR_ID_AMD && device->architecture != AMD_GCN &&
    n_rows >= 4 && hsk == 128 && hsv == 128) {
    result.disable_subgroups = true;
}
```

- 影响 AMD 非 GCN、D=128、行数 ≥4 的所有形状。第一版门槛设为 `n_rows>=64`（只覆盖 DiT 的
  self-attention），但 1440×1920 的 A/A 复测显示**文本编码器**（Qwen3.5-9B，42 个 token）的
  注意力也会偶发同样的问题，于是把门槛放宽到 4（保留纯 decode 的 n_rows<4 原路径）。
- 纯 decode（n_rows < 4）与其它 head_dim 的形状不动。
- Occupancy limiter（hsk ≤ 64 的 30 KB 路径）不受影响；INT8 GEMM 不受影响。

| 项目 | 结果 |
|---|---|

| 隔离重复调用 L=10812 | 1000 次 0 差异 |
| Occupancy 路径（hsk≤64） | 未改动（代码路径独立） |
| A/A 端到端 1024² ×3 | 见 §5 |

## 5. 端到端 A/A

同一 Recipe / seed / prompt，逐步导出 `dctx` / `dx` / 每步 `lin` / 每步 `pred`，逐位比较：

| 分辨率 | 批次 | 运行次数 | 结果 |
|---|---|---|---|
| 1440×1920 | 修复后（第一版门槛 n_rows≥64） | 3 | 全部逐位一致 |
| 1440×1920 | 放宽门槛后 + 清理诊断钩子后 | 1 + 1 | 与上面逐位一致（4/4） |
| 1024×1024 | 修复后 | 3 + 1 | 3 次一致，**1 次在 `pred` 第 1 步分歧** |
| 1024×1024 | 带层导出复测（8 步 × 3 次） | 3 | 全部逐位一致 |
| 1024×1024 | 隔离复测：FA L=4138 | 295 次调用 | 0 异常 |
| 1024×1024 | 隔离复测：i8 GEMM 三种形状 | 各 3 次 | FNV 哈希一致 |
| 任意 | 融合 rms_norm（我们的改动） | 200 次重复 | 0 差异 |

采样时间：1440×1920 134.4 / 134.2 / 133.9 s，1024² 38.5–40.3 s（与修复前持平或略快）。

## 6. 遗留（未完成项，明确记录）

1. **1024² 仍有一次残余分歧**（6 次运行中的 1 次，`pred` 第 1 步即不同，输入 `dx`/`dctx` 相同）。
   已排除：FA（295 次隔离调用 0 异常）、i8 GEMM（三形状 ×3 次哈希一致）、融合 rms_norm（200 次重复一致）、
   文本编码器（同 prompt 下 1440 的 4 次运行一致）。**尚未定位**，需要下一阶段继续（建议：在分歧发生时
   用 canary/双跑对比法逐 op 二分，或对 1024² 的 batched-CFG 形状做 FA 隔离测试）。
2. subgroup 路径在 RADV 上的具体失效机制未定位到指令级；本修复是"绕开该路径"（且它更慢）。
3. 若上游修复该路径，可重新评估；当前无收益动机。

## 7. 结论

- **已修复并验收**：1440×1920（生产分辨率）4/4 运行逐位一致；FA 隔离 1295 次调用 0 异常；精度与 CPU
  参考一致（rms 5.94e-06）；性能不降反升（FA −7 %）。
- **未完成**：1024² 的残余不确定性（1/6），来源未定位。因此不宣称"确定性已完全恢复"。
